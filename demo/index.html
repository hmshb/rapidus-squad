Design spec — how Casey actually renders
Chapter 8 · interactive UX spec

The canonical Casey-in-Slack UX (Cursor-style)

Every Casey response renders as one mutating message: idle → working → complete | cancelled | failed. Working state shows a TodoWrite checklist that updates progressively. Completion collapses to a summary card with action buttons (View PR, View logs, overflow menu with Follow-up / Re-run / Feedback / Delete). Four scenarios — bugfix, QA, lookup, failure — all interactive. This is the production UX the FE agent should build. Chapters 3, 4, and the elevator use a parallel "stream of messages" pattern for the split-pane sandbox-visible mode; this chapter is the canonical default.
