What's different in the proposed version

  • Tool-aware inline status — Casey edits ONE message with text that reflects what the agent is doing right now (Reading code…, Searching the codebase…, Writing changes…) instead of a generic Thinking… animation.
  • Slack-native footer indicator — assistant.threads.setStatus shows "Casey is thinking…" right above the composer. Always visible while work is in flight, disappears the instant Casey replies — no cleanup needed.
  • No "Task completed" message — the placeholder transitions directly into the final reply, eliminating one chat message. Cleaner thread.
  • Status updates driven by stream events — every tool-use event coming through stream-json maps to a status string. No timers, no guesses about which phase we're in.
